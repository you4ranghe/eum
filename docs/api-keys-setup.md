# API 키 발급 가이드 (WBS W1-0)

> **읽는 사람**: 지도 API 콘솔을 처음 다루는 사람
> **소요 시간**: 순수 작업 40~60분 + 네이버 심사 대기(보통 즉시~수 시간)
> **끝나면**: `.env.local`에 값 9개가 채워지고 지도가 뜬다

---

## ⚠️ 시작 전에 반드시 알 것

### 1) 카드 등록은 피할 수 없다

**네이버 클라우드 플랫폼과 Google Cloud 모두 결제수단 등록이 필수**다.
"무료로만 쓸 건데 왜?"라고 생각되겠지만, 무료 한도를 넘는 순간을 대비한 담보다.

**그래서 이 가이드에서 가장 중요한 단계는 키 발급이 아니라 "상한 설정"이다.**
키 발급만 하고 상한을 안 걸면, 키가 유출되거나 코드에 무한 루프가 하나만 있어도
며칠 만에 수십만 원이 청구될 수 있다. 실제로 개발자 커뮤니티에서 정기적으로 터지는 사고다.

### 2) 네이버는 **서로 다른 두 개의 서비스**다

이걸 모르면 401 오류를 며칠간 붙잡게 된다. 나도 처음 코드를 짤 때 하나로 착각했다.

| | 네이버 클라우드 플랫폼 | 네이버 개발자센터 |
|---|---|---|
| 주소 | console.ncloud.com | developers.naver.com |
| 이 앱에서 쓰는 것 | **지도 표시**, **길찾기** | **장소 검색** |
| 요금 | 유료 (무료 한도 있음) | 무료 (일 25,000회) |
| 카드 등록 | **필수** | 불필요 |
| 인증 헤더 | `x-ncp-apigw-api-key-id` | `X-Naver-Client-Id` |

**계정도 키도 완전히 별개다.** 둘 다 만들어야 한다.

### 3) 그래서 총 4곳에서 키를 받는다

```
① 네이버 클라우드 플랫폼  → 지도 표시 + 길찾기      (키 3개)
② 네이버 개발자센터        → 장소 검색              (키 2개)
③ Google Cloud            → 지도/검색/경로 백업     (키 2개)
④ Supabase                → DB (M2에서, 지금은 생략)
```

# ① 네이버 클라우드 플랫폼 — 지도 표시 + 길찾기

## 1-1. 가입 및 결제수단 등록

1. https://www.ncloud.com 접속 → **회원가입**
2. 개인 회원으로 가입 (사업자 아니어도 됨)
3. 휴대폰 본인인증
4. 로그인 후 우측 상단 **마이페이지 → 결제수단 관리**
5. 신용/체크카드 등록

> 💡 등록 시 100원 정도가 결제됐다가 취소되는 경우가 있다. 정상이다.

## 1-2. Maps 서비스 이용 신청

1. 상단 **콘솔** 클릭 → https://console.ncloud.com
2. 왼쪽 메뉴에서 **Services** → **Application Services** → **Maps**
   - 메뉴 구조가 개편될 수 있다. 안 보이면 콘솔 상단 검색창에 `Maps` 입력
3. **이용 신청하기** 클릭
4. 약관 동의 → 신청 완료

## 1-3. Application 등록 (여기서 키가 나온다)

1. Maps 화면에서 **Application 등록** 클릭
2. **Application 이름**: `eum` (아무거나)
3. **Service 선택** — 아래 3개를 체크한다:
   - ☑️ **Web Dynamic Map** ← 지도를 화면에 그린다
   - ☑️ **Directions 5** ← 길찾기 (동선 계산, WBS W3-3에서 사용)
   - ☑️ **Geocoding** ← 주소 ↔ 좌표 변환 (나중에 쓸 수 있으니 미리)
4. **Web 서비스 URL** — 이게 사실상 도메인 제한이다. 정확히 입력할 것:
   ```
   http://localhost:3000
   ```
   나중에 Vercel 배포 후 배포 주소(`https://eum-xxx.vercel.app`)를 추가한다.

   > ⚠️ 흔한 실수: 끝에 슬래시(`/`)를 붙이거나 `localhost:3000`처럼 `http://`를 빼면
   > 인증 오류가 난다. 프로토콜 포함, 슬래시 제외.

5. **등록** 클릭

## 1-4. 키 확인

1. 등록된 Application의 **인증 정보** 버튼 클릭
2. 두 종류가 보인다:

| 콘솔 표기 | `.env.local` 변수 | 용도 |
|---|---|---|
| **Client ID** 또는 **Key ID** | `NEXT_PUBLIC_NCP_MAP_KEY_ID` | 브라우저에서 지도 로드 |
| **Access Key ID** | `NCP_API_KEY_ID` | 서버에서 길찾기 호출 |
| **Secret Key** | `NCP_API_KEY` | 서버에서 길찾기 호출 |

> Access Key / Secret Key는 **마이페이지 → 인증키 관리**에 있는 계정 단위 키다.
> Application의 Client ID와는 다른 것이니 헷갈리지 말 것.

## 1-5. 🚨 요금 상한 설정 (가장 중요)

1. 콘솔 우측 상단 **마이페이지** → **요금 알림 설정** (또는 **Billing → 알림 설정**)
2. **알림 임계값** 설정: 예) `10,000원`
3. 알림 수신 이메일/SMS 등록

> ⚠️ 네이버 클라우드는 **자동 차단 기능이 약하다.** 알림만 오고 서비스는 계속된다.
> 그래서 이 앱은 코드 레벨에서 방어한다:
> - 경로 계산은 자동이 아니라 **버튼을 눌러야만** 호출된다
> - 계산 결과는 `route_leg_cache` 테이블에 캐시되어 재호출되지 않는다
>
> 그래도 알림은 반드시 켜둘 것. 이상을 아는 유일한 수단이다.

**무료 한도**는 서비스별로 다르고 자주 바뀐다.
콘솔의 **Maps → 요금** 탭에서 직접 확인할 것. (여기 숫자를 적어두면 금방 낡는다)

# ② 네이버 개발자센터 — 장소 검색

여기는 훨씬 간단하다. 카드도 필요 없다.

1. https://developers.naver.com 접속 → 네이버 아이디로 로그인
2. 상단 **Application** → **애플리케이션 등록**
3. **애플리케이션 이름**: `eum`
4. **사용 API**: **검색** 선택
5. **비로그인 오픈 API 서비스 환경**: **WEB 설정** 선택
   - 웹 서비스 URL: `http://localhost:3000`
6. **등록하기**
7. 등록 후 **Client ID**와 **Client Secret**이 보인다

| 콘솔 표기 | `.env.local` 변수 |
|---|---|
| Client ID | `NAVER_SEARCH_CLIENT_ID` |
| Client Secret | `NAVER_SEARCH_CLIENT_SECRET` |

**무료 한도: 일 25,000회.** 개인 프로젝트에서 절대 못 넘는다. 걱정 안 해도 된다.

> 📌 알아둘 한계: 네이버 지역 검색은 **한 번에 최대 5건**만 반환하고,
> **영업시간을 주지 않는다.** 그래서 영업 상태 표기는 구글 Places로 보강한다(WBS W3-2).

# ③ Google Cloud — 지도 / 검색 / 경로

## 3-1. 프로젝트 생성 및 결제 계정 연결

1. https://console.cloud.google.com 접속 → 구글 계정 로그인
2. 상단 프로젝트 선택기 → **새 프로젝트**
   - 프로젝트 이름: `eum`
3. 좌측 메뉴 **결제** → **결제 계정 연결**
4. 카드 등록 (신규 가입 시 $300 크레딧이 붙는 경우가 있다)

## 3-2. API 3개 활성화

좌측 메뉴 **API 및 서비스** → **라이브러리** 에서 아래를 검색해 각각 **사용 설정**:

| API 이름 | 용도 |
|---|---|
| **Maps JavaScript API** | 구글 지도 렌더링 (브라우저) |
| **Places API (New)** | 장소 검색 + 영업시간 (서버) |
| **Routes API** | 경로 계산 (서버) |

> ⚠️ **Places API**와 **Places API (New)**는 다른 API다. 반드시 **(New)** 쪽을 켤 것.
> 코드가 `places.googleapis.com/v1/places:searchText`를 호출하는데, 이건 New 전용이다.

## 3-3. 키 2개 만들기 (하나로 쓰면 안 된다)

**API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → API 키**

### 키 A — 브라우저용

1. 생성된 키의 **이름 수정**: `eum-browser`
2. **애플리케이션 제한사항** → **HTTP 리퍼러(웹사이트)** 선택
3. 리퍼러 추가:
   ```
   http://localhost:3000/*
   https://*.vercel.app/*
   ```
4. **API 제한사항** → **키 제한** → **Maps JavaScript API** 만 선택
5. 저장 → `.env.local`의 `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY`

### 키 B — 서버용

1. 새 API 키 생성 → 이름: `eum-server`
2. **애플리케이션 제한사항** → **없음**
   > 왜 제한을 안 거는가: 서버는 **리퍼러 헤더를 보내지 않는다.**
   > 리퍼러 제한을 걸면 모든 요청이 거부된다.
   > Vercel은 IP가 고정되지 않아 IP 제한도 못 쓴다.
   > → 그래서 **API 제한**으로만 방어하고, 키를 절대 클라이언트에 노출하지 않는다.
   > (`NEXT_PUBLIC_` 접두사를 붙이지 않는 이유가 이것이다)
3. **API 제한사항** → **키 제한** → **Places API (New)** + **Routes API** 선택
4. 저장 → `.env.local`의 `GOOGLE_MAPS_SERVER_KEY`

## 3-4. 🚨 할당량 상한 설정 (진짜 방어선)

**예산 알림과 할당량 상한은 다르다. 반드시 둘 다 해야 한다.**

### (1) 할당량 상한 — 실제로 차단한다

1. **API 및 서비스** → **할당량 및 시스템 한도**
2. 상단 필터에서 서비스 선택 (예: `Maps JavaScript API`)
3. `Map loads per day` 같은 일일 할당량 항목 체크
4. **할당량 수정** → 값을 낮게 설정 (예: `1000`)
5. Places API (New), Routes API도 동일하게 반복

> 개인 프로젝트에서 하루 1,000회면 충분히 넉넉하다.
> 넘으면 API가 거부되고 요금은 발생하지 않는다.

### (2) 예산 알림 — 알려주기만 한다

1. **결제** → **예산 및 알림** → **예산 만들기**
2. 이름: `eum-budget`, 금액: `10,000원`
3. 알림 임계값: 50% / 90% / 100%
4. 이메일 수신 체크

> ⚠️ **예산은 서비스를 차단하지 않는다.** 이메일만 온다.
> 자고 있는 사이에 터지면 알림은 아무 소용이 없다.
> **실제 차단은 (1) 할당량 상한만 할 수 있다.** 둘 다 하는 이유다.

## 3-5. 요금 구조 참고

2025년 3월에 기존 "월 $200 크레딧"이 **API별 월 무료 호출 수**로 바뀌었다.
대략 Essentials 등급 월 10,000회 / Pro 5,000회 / Enterprise 1,000회 수준이지만,
등급 분류와 수치는 변동이 잦으니 **콘솔의 요금 페이지에서 확인**할 것.

개인이 개발하며 쓰는 수준에서는 무료 한도를 넘기 어렵다.
**위험한 건 사용량이 아니라 사고(키 유출·무한 루프)다.** 그래서 상한이 중요하다.

# ④ 마무리 — `.env.local` 작성

프로젝트 루트에서:

```bash
cp .env.local.example .env.local
```

`.env.local`을 열어 값을 채운다:

```env
NEXT_PUBLIC_NCP_MAP_KEY_ID=여기에_Client_ID
NCP_API_KEY_ID=여기에_Access_Key_ID
NCP_API_KEY=여기에_Secret_Key

NAVER_SEARCH_CLIENT_ID=여기에_개발자센터_Client_ID
NAVER_SEARCH_CLIENT_SECRET=여기에_개발자센터_Client_Secret

NEXT_PUBLIC_GOOGLE_MAPS_API_KEY=여기에_브라우저용_키
GOOGLE_MAPS_SERVER_KEY=여기에_서버용_키
```

그리고:

```bash
npm run dev
```

http://localhost:3000 에서 제주도 지도가 뜨면 성공이다.

> ⚠️ `.env.local`은 `.gitignore`에 있어 커밋되지 않는다. **절대 커밋하지 말 것.**
> GitHub에 올라간 키는 몇 분 안에 자동 스캐너에 수집된다.

# 문제 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 지도 영역에 "NEXT_PUBLIC_NCP_MAP_KEY_ID 미설정" | 환경변수 미입력 | `.env.local` 확인 후 **dev 서버 재시작** (환경변수는 재시작해야 반영된다) |
| 네이버 지도가 회색이고 콘솔에 인증 오류 | Web 서비스 URL 불일치 | NCP 콘솔의 URL이 정확히 `http://localhost:3000`인지 (슬래시·프로토콜) |
| 구글 지도에 "For development purposes only" 워터마크 | 결제 계정 미연결 | Google Cloud 결제 계정 연결 |
| 구글 지도 `RefererNotAllowedMapError` | 리퍼러 제한 불일치 | 키 A 리퍼러에 `http://localhost:3000/*` (와일드카드 `*` 포함) |
| 장소 검색 401 | 네이버 두 서비스 혼동 | 검색은 **개발자센터** Client ID/Secret. NCP 키가 아니다 |
| 장소 검색 결과가 5개뿐 | 정상 | 네이버 지역 검색의 사양 한계 |
| 경로 계산 401 | NCP Directions 5 미신청 | NCP Maps Application에서 Directions 5 체크 |
